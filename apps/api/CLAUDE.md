# 백엔드 규칙 (apps/api)

> 대상: AI

## 스택
docs/engineering/tech-stack.md를 따른다. 이 파일에는 백엔드에만 해당하는 실행 방법과 규칙만 둔다.

## 명령
- 개발 서버: <명령>
- 테스트: <명령>
- DB 마이그레이션: <명령>

## 규칙
- 엔드포인트는 OpenAPI 계약을 먼저 고친 뒤 구현한다. API가 돌려줄 데이터는 docs/design/ux.md 화면 목록의 "필요한 데이터"를 기준으로 한다.
- 승인된 스펙에 없는 기능은 구현하지 않는다.
- 테스트를 먼저 쓴다. 인수 기준마다 테스트가 하나 이상 있어야 한다.
- DB 스키마 변경은 마이그레이션 파일로만 한다.
- 시크릿은 환경 변수로만 읽는다. .env 파일을 읽거나 출력하지 않는다.
- DB MCP는 개발 DB에만 연결한다.
- 입력 검증, 비즈니스 로직, DB 접근을 분리한다(라우터에 로직을 두지 않는다).
- 인증·권한 검사는 모든 보호 엔드포인트에서 서버가 한다.
- 외부 AI API는 서버에서만 호출하고, 타임아웃·재시도·사용량 상한을 둔다.

## 응답·에러 형식
<3단계에서 확정. 모든 엔드포인트가 같은 형식을 쓴다. 예:>
```json
{ "data": { }, "error": null }
{ "data": null, "error": { "code": "VALIDATION_FAILED", "message": "사용자에게 보여 줄 문장", "details": [] } }
```
| 상황 | HTTP 상태 | error.code |
|---|---|---|
| 입력 오류 | 400 | VALIDATION_FAILED |
| 인증 필요 | 401 | UNAUTHENTICATED |
| 권한 없음 | 403 | FORBIDDEN |
| 없음 | 404 | NOT_FOUND |
| 서버 오류 | 500 | INTERNAL |
