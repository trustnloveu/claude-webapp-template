# 스펙 작성 기준

> 대상: 공용

> 작성: Agent 01 기획(planner) · 확정: 사람(기획 승인)

Spec Kit이 저장소 루트의 `specs/00N-<이름>/`에 만드는 스펙에 아래 항목이 모두 들어가도록 합니다. 스펙 위치는 Spec Kit 기본값을 따르고, 이 문서는 작성 기준만 둡니다.
스펙은 docs/planning/requirements.md의 분석과 질문의 답을 바탕으로 씁니다. 화면 구성(IA, 화면 목록)은 디자인 단계의 docs/design/ux.md가 맡습니다.

## PRD 목차
1. 개요와 목표
2. 타깃 사용자 (docs/planning/idea.md 페르소나 참조)
3. 사용자 문제 정의
4. 핵심 기능과 기능별 상세 요구사항 (아래 기능 명세 표)
5. 사용자 시나리오 (`flows.md`, 텍스트 또는 Mermaid. 화면 단위가 아니라 사용자 행동 단위)
6. 비기능 요구사항: 성능, 보안, 접근성, 지원 브라우저·기기, 개인정보
7. MVP 범위 (MoSCoW) (사람 결정)
8. 향후 확장 계획 (Could, Won't)
9. 성공 지표(KPI)
10. 가정과 미결정 질문 (requirements.md의 "질문과 답"과 연결)
11. 요구사항 추적 (requirements.md의 추적표)

## 인수 기준
기능마다 Given-When-Then으로 적습니다.
```text
F-001-1  Given <상황>  When <행동>  Then <결과>
```

## MoSCoW 기준
Claude는 분류를 `(제안)`으로 적고, 사람이 최종 분류를 확정합니다.

| 분류 | 의미 |
|---|---|
| Must | 없으면 첫 사용자가 핵심 가치를 느끼지 못함. MVP에 포함 |
| Should | 중요하지만 MVP 직후로 미뤄도 됨 |
| Could | 있으면 좋음. 여유가 있을 때 |
| Won't | 이번 버전에서는 하지 않음. 이유를 함께 기록 |
