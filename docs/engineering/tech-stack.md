## 3. 구조와 디자인 패턴

### 폴더 구조
```text
apps/web/src/
  <4단계에서 확정>
apps/api/src/
  <4단계에서 확정>
```

### 계층과 책임
| 계층 | 위치 | 책임 | 하면 안 되는 것 |
|---|---|---|---|
| 라우터·컨트롤러 | | 요청 파싱, 응답 변환 | 비즈니스 로직, DB 직접 접근 |
| 서비스(도메인) | | 비즈니스 규칙 | HTTP 객체 다루기 |
| 저장소(리포지토리) | | DB 접근 | 비즈니스 규칙 |
| 화면 컴포넌트 | | 표시와 사용자 입력 | API 직접 호출(데이터 훅·클라이언트 사용) |

### 패턴 규칙
- 상태 관리: <서버 상태와 화면 상태를 어떻게 나누는지>
- 에러 처리: 백엔드는 apps/api/CLAUDE.md의 응답·에러 형식, 프론트엔드는 <에러 경계·토스트 방식>
- 데이터 검증: <스키마 검증 라이브러리, 어디서 검증하는지>
- 이름 규칙: 파일 <kebab-case 등>, 컴포넌트 <PascalCase 등>, DB 테이블·컬럼 <snake_case 등>
- 테스트 위치·이름: <규칙>

### 구현 순서 (최소 구현)
구현 에이전트는 바꿀 코드와 그 코드를 부르는 곳을 먼저 읽고, 아래에서 처음으로 되는 방법을 고릅니다. reviewer는 이 순서를 어긴 코드를 "품질" 지적으로 봅니다.
1. 꼭 필요한가: 요청·스펙에 없는 기능·옵션·확장 포인트는 만들지 않고 보고에 한 줄로 남깁니다
2. 이미 이 코드에 있는가: 있는 함수·컴포넌트·패턴을 주변 코드와 같은 방식으로 씁니다
3. 언어 표준 기능이나 브라우저·플랫폼 기본 기능으로 되는가 (프로젝트에 자체 컴포넌트가 있으면 그것이 먼저)
4. 이미 설치된 라이브러리로 되는가: 몇 줄 때문에 새 라이브러리를 들이지 않습니다(4장 추가 규칙)
5. 그래도 안 되면 동작하는 최소 코드
- 줄이면 안 되는 것: 외부 입력 검증, 데이터 손실을 막는 에러 처리, 보안, 접근성, 요청받은 것
- 분기·반복·파싱·돈·보안이 있는 새 로직은 작은 테스트를 하나 이상 남깁니다(TDD 규칙과 같음)
- 알고 쓰는 지름길은 `shortcut: <한계>, <언제 바꿀지>` 형식의 주석을 남깁니다
- 작업 보고 끝에 건너뛴 것·확인하지 못한 것·알아야 할 위험을 한두 줄로 적습니다

### 코드 크기와 테스트 기준 (사람 결정)
reviewer와 qa가 이 숫자로 판정합니다. 넘으면 "중간" 지적이며, 이유가 있으면 예외를 둘 수 있습니다. 테스트·자동 생성 파일은 제외합니다.

| 항목 | 기준 |
|---|---|
| 함수 길이 | 50줄 이하 (제안) |
| 파일 길이 | 보통 200~400줄, 최대 800줄 (제안) |
| 중첩 깊이 | 4단계 이하, 넘으면 조기 반환(early return)으로 줄임 (제안) |
| 테스트 커버리지 | 80% 이상 (제안) |
| 테스트 구조 | 준비-실행-확인(Arrange-Act-Assert), 테스트 이름은 기대 동작을 문장으로 (제안) |

### 추가 규칙
1. 작업 에이전트는 직접 설치하지 않고 이유와 함께 총괄에 요청한다.
2. 총괄이 후보(이미 있는 라이브러리로 해결 가능한지 포함), 크기, 유지보수 상태, 라이선스를 정리해 "사람 확인 대기"에 올린다.
3. 사람이 승인하면 설치하고 위 표에 추가한다.
4. 같은 용도의 라이브러리를 두 개 두지 않는다.

## 6. 보안 기준 (사람 결정)
3단계에서 스택을 정할 때 함께 확정합니다. 구현 에이전트는 따르고, reviewer는 이 기준으로 리뷰합니다.

| 항목 | 기준 |
|---|---|
| 시크릿 | 코드·로그·에러 메시지에 넣지 않음. 서버 시작 때 필수 환경 변수가 있는지 확인 (제안) |
| 입력 검증 | 외부 입력은 들어오는 지점에서 스키마로 검증, 허용 목록 방식 (제안) |
| DB 쿼리 | 파라미터 바인딩 또는 ORM만 사용, 문자열 이어 붙이기 금지 (제안) |
| 로그인 토큰 보관 | localStorage 금지, httpOnly·Secure·SameSite 쿠키 (제안) |
| 권한 확인 | 모든 API에서 서버가 인증·권한을 확인, 화면 숨김만으로 막지 않음 (제안) |
| XSS | 사용자 입력을 HTML로 직접 넣지 않음, CSP는 `default-src 'self'`부터 시작 (제안) |
| CSRF | 쿠키 인증을 쓰면 SameSite와 CSRF 토큰으로 막음 (제안) |
| 요청 횟수 제한 | 로그인·검색·쓰기 API에 제한 적용, 수치는 3단계에서 정함 (제안) |
| 에러 응답 | 사용자에게는 쉬운 메시지, 스택·내부 정보는 서버 로그에만 (제안) |
| 로그 | 비밀번호·토큰·카드 번호 등 민감정보를 남기지 않음 (제안) |
| 외부 호출 | 타임아웃 필수, 사용자가 준 URL로 요청하면 허용 목록 확인 (제안) |
| 파일 업로드 | 크기 상한과 형식(MIME·확장자) 허용 목록, 수치는 3단계에서 정함 (제안) |
| CORS | 허용 출처를 명시, 전체 허용(`*`) 금지 (제안) |
| 의존성 | 출시 전 취약점 점검(`npm audit` 등), lock 파일 커밋 (제안) |
