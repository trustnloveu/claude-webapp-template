# 5단계. 출시·운영

> 대상: 사람

저장 위치: `docs/reports/`, `docs/engineering/deploy.md`, 릴리스 노트

## 전체 기능 테스트 (원본 ㉓)
```text
출시 전 전체 기능을 점검해 줘.
기능, API, DB, 입력 검증, 인증·권한, 예외 상황, 브라우저 호환성, 반응형.
docs/reports/test-report-template.md 형식으로 docs/reports/<날짜>-test.md에 저장하고,
문제는 심각도별로 분류해. 실제로 실행한 테스트와 실행하지 못한 테스트를 구분해.
```

## 코드 리뷰와 리팩토링 (원본 ㉕)
```text
전체 코드를 리뷰해 줘. 품질, 중복, 성능, 보안, 예외 처리, 유지보수성, 불필요한 의존성.
문제와 개선안, 영향 범위를 먼저 보고만 해. 리팩토링은 항목별로 내가 승인한 것만, PR을 나눠서 해.
```

## 배포 환경 (원본 ㉖)
```text
[배포처]에 운영 환경을 구성해 줘. 스테이징과 운영을 분리해.
환경 변수, 빌드·배포 설정, 도메인·HTTPS, DB 연결, 로그, 배포 후 정상 동작 확인.
결과를 docs/engineering/deploy.md에 반영하고, 롤백 절차를 실제로 한 번 실행해 확인해.
시크릿 값은 내가 배포처에 직접 넣을게.
```

## 보안 점검 (원본 ㉗)
```text
/security-review를 실행하고 다음 항목을 추가로 확인해 줘.
인증·권한, API 키 노출, SQL Injection, XSS, CSRF, 입력 검증, 파일 업로드, 개인정보, 데이터 접근 권한.
위험도별로 분류해 docs/reports/<날짜>-security.md에 저장하고, 수정 방안을 제시해.
```

## 성능 (원본 ㉘)
```text
성능을 측정하고 개선해 줘. 초기 로딩, 이미지, 번들 크기, 렌더링, API 응답 시간, DB 쿼리, 캐싱, Core Web Vitals.
먼저 실제 측정값을 기록하고, 개선 후 같은 방법으로 다시 측정해 전후 수치를 표로 비교해.
추정치는 측정값과 섞지 마.
```

## 모니터링 (원본 ㉙)
```text
초기 서비스용 모니터링을 설계해 docs/engineering/deploy.md의 "모니터링"을 채워 줘.
서버 상태, API 오류, 사용 통계, DB 상태, AI API 사용량·비용, 장애 알림, 로그.
항목마다 추천 도구 1개와 도입 시점(출시 전 / 출시 후)을 정하고, 출시 전 항목은 구현해.
```

## 고도화 (원본 ㉚) — 다음 버전의 1~2단계 입력
```text
운영 데이터와 들어온 요청(이슈, 스펙 Later 목록)을 분석해 다음 개선 과제를 정리해 줘.
사용자 불편, 사용률 낮은 기능, 추가 기능, UX, 성능, AI 기능, 수익 모델.
과제마다 기대 효과, 난이도, 우선순위를 평가하고, 선택한 과제는 specs/00N-<이름>/ 스펙으로 시작해.
```
