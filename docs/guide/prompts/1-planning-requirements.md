# 1단계. 기획 (1/2) — 요구사항 분석과 아이디어

> 대상: 사람

담당: Agent 01 기획(planner). 질문은 총괄이 중계합니다. 저장 위치: `docs/planning/requirements.md`, `docs/planning/idea.md`
기획은 프로젝트에서 가장 중요한 단계입니다. 여기서 정한 것이 디자인과 구현의 기준이 됩니다.

## 요구사항 분석 (기획 리드, 템플릿 추가)
총괄이 원문을 docs/planning/requirements.md에 남긴 뒤 planner에게 맡깁니다.
```text
docs/planning/requirements.md의 원문을 분석해 줘(planner, 분석 모드).
목적, 사용자 유형, 기능·비기능 요구사항, 모호한 표현, 빠진 정보, 충돌, 실현 가능성과 위험을 "분석"에 정리하고,
나에게 물어야 할 것은 "질문과 답" 표에 선택지와 각 선택의 영향을 붙여 정리해 줘.
질문은 중요한 것부터 한 번에 5개 이내로 보여 줘.
```

## 아이디어 구체화 (원본 ①)
```text
나는 [서비스 분야] 웹앱을 만들려고 해. 바로 답을 주지 말고 내가 놓친 점을 질문으로 하나씩 물어봐.
충분히 정리되면 docs/planning/idea.md 템플릿의 항목을 채워 줘:
한 문장 정의, 해결할 문제, 타깃 사용자, 현재 대안, 핵심 가치, 차별화, 수익 모델, MVP 핵심 기능 후보, 성공 기준, 하지 않을 것.
확정한 내용과 가정을 구분해서 적어.
```

## 경쟁 서비스 분석 (원본 ②)
```text
[서비스 분야]의 국내외 경쟁 서비스 3~5개를 웹에서 조사해 줘.
서비스마다 주요 기능, 타깃, UI/UX 특징, 강점·약점, 수익 모델을 표로 정리하고, 각 행에 출처 링크를 붙여.
출처를 확인하지 못한 내용은 "미확인"으로 표시해.
결과를 바탕으로 차별화 전략을 제안하고 docs/planning/idea.md의 "경쟁 서비스"와 "차별화"에 반영해.
```

## 페르소나 (원본 ③)
```text
docs/planning/idea.md를 바탕으로 핵심 사용자 페르소나를 3개 만들어 줘.
각각 가상 프로필, 목표, 불편 사항, 이용 목적, 주요 사용 시나리오, 필요한 핵심 기능을 적어.
실제 조사 결과가 아닌 가설이라는 표시를 붙여서 docs/planning/idea.md의 "페르소나"에 넣어.
```
