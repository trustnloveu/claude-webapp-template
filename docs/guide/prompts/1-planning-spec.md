# 1단계. 기획 (2/2) — 정형화와 고도화

> 대상: 사람

담당: Agent 01 기획(planner). 저장 위치: `specs/001-mvp/`, `docs/planning/requirements.md`
스펙에는 기술 용어를 쓰지 않고, 화면 구성(IA, 화면 목록)도 정하지 않습니다. 끝에 **기획 승인**을 받습니다.

## PRD (원본 ④)
```text
docs/planning/requirements.md의 분석과 질문의 답, docs/planning/idea.md를 바탕으로 Spec Kit specify로 MVP 스펙을 만들어 줘(planner, 정형화 모드).
docs/planning/spec-guide.md의 "PRD 목차"를 모두 포함하고, 기능마다 Given-When-Then 인수 기준을 붙여.
확정된 요구사항, 가정, 미결정 질문을 구분하고, 미결정 질문은 따로 목록으로 뽑아.
```

## 기능 명세 (원본 ⑤)
```text
스펙의 기능을 docs/planning/spec-guide.md의 "기능 명세 표" 형식으로 정리해 줘.
기능 ID, 기능명, 설명, 사용자 유형, 입력, 처리, 출력, 예외 상황, 권한, 우선순위를 채우고
대분류·중분류로 묶어.
```

## MVP 우선순위 (원본 ⑥)
```text
기능 명세의 모든 기능을 MoSCoW(Must / Should / Could / Won't)로 분류해 줘.
기능마다 사용자 가치, 개발 난이도, 다른 기능과의 의존성을 상/중/하로 평가하고 근거를 한 줄씩 적어.
Must는 "이것 없이는 첫 사용자가 핵심 가치를 못 느끼는 것"만 남겨. 최종 결정은 내가 할게.
```

## 사용자 시나리오 (원본 ⑧ 조정)
```text
Must 기능의 사용자 시나리오를 써 줘. 화면 단위가 아니라 사용자 행동 단위로 쓰고, 화면 구성은 정하지 마(디자인 단계).
진입 경로, 단계별 행동, 화면 전환, 시스템 처리, 분기 조건, 성공·실패 시나리오를 포함하고
Mermaid flowchart로 specs/001-mvp/flows.md에 저장해. 예외 흐름도 빠뜨리지 마.
```

## 기획 고도화 (템플릿 추가)
```text
확정된 스펙을 고도화 관점에서 검토해 줘(planner, 고도화 모드).
빠진 예외 흐름, 사용자 입장의 불편, 경쟁 서비스 대비 부족한 점, 측정 가능한 성공 지표를 찾고
docs/planning/requirements.md "고도화 제안"에 기대 효과·난이도·우선순위(제안)와 함께 적어. 스펙에는 직접 반영하지 마.
```

## 추적 확인과 기획 승인 요청 (템플릿 추가)
```text
requirements.md의 원문 항목이 모두 스펙의 기능 ID로 반영됐는지 추적표를 채우고,
반영하지 않은 항목은 이유를 적어 줘. 그다음 기획 승인을 받을 수 있게 요약해 줘:
Must 기능 목록, 남은 미결정 질문, 내가 결정해야 할 MoSCoW 항목.
```
